# Media intake and human-authorized agent checkout
The bounded workflow collects up to 12 destination lead images from Wikimedia Commons (CC BY and CC BY-SA 3.0/4.0, or CC0 only), records original creator, exact licence, source URL, checksum and media type, and writes content-addressed bytes and sidecar JSON under intake/commons/ in the existing private development R2 bucket. No lifecycle change or public domain assignment. These are machine-filtered candidates, not human-approved or destination-verified assets. Do not expose the bucket directly. Source review, attribution display, share-alike compliance for adaptations, image suitability, and D1 approval are required before serving any media. Videos, food, music, culture, animations and global-scale intake remain separate rights review work. Run the main-branch Collect permanent RoamWise media candidates workflow with COLLECT-PRIVATE-MEDIA if the initial push run has not executed. Check the artifact and bucket counts; workflow failures do not establish upload success.

Agent proposes specific catalogue IDs only; the user clicks review, verifies price, then explicitly taps Cashfree. Existing stay/shop workers reject an expected amount mismatch before order creation. Quote lifetime five minutes; current review cannot initiate a second attempt after payment creation starts. This does not provide end-to-end cross-device idempotency, automatic delegated spending, or Cashfree mandate/one-click UPI authentication. No actual payments or new payment permissions. Browser, live sandbox and webhook testing remain release gates. The realtime voice endpoint is not configured in tracked app code: standard voice parity is in PR #880; live validation requires a secure authenticated provider session and browser/mic testing. Do not turn on a paid route until budget, entitlement and usage gates pass.
